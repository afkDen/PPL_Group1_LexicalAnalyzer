# Ternfold C lexical analyzer

Standalone ISO C17 scanner. It needs an installed Clang/GCC compiler; no Python,
Node, internet, AI service or full compiler is required. Windows LLVM-MinGW Clang
23.1.4 is verified. POSIX/GCC/MSVC have not been executed in this environment.

```powershell
./scripts/build.ps1 environment
./scripts/build.ps1 check
./build/ternfold-lexer.exe examples/lexical/complete.tfd --output-dir build
./build/ternfold-lexer.exe examples/lexical/invalid.tfd --output-dir build
```

Use `-Compiler 'C:/path/to/clang.exe'` or CC when needed. `build.bat check` also
works. On POSIX the intended command is `sh scripts/build.sh check`; run
`./build/ternfold-lexer examples/lexical/complete.tfd --output-dir build`.
For supported Clang installations, `scripts/build.ps1 sanitize` runs ASan/UBSan.

Only exact `.tfd` source extensions are accepted. Output directories must exist.
Exit 0 means valid input, 1 source/lexical errors, 2 usage/host/output failure.
The invalid example intentionally exits 1. Lexing reports tokens, not parsing,
typing, integer overflow or execution. All integers/floats retain source spelling.

`Symbol Table.txt` has exactly TOKEN TYPE and LEXEME, separated by a tab.
Lexemes are JSON quoted with reversible escapes for newlines/tabs/quotes/control
bytes. Comments and invalid rows remain in source order; whitespace and EOF are
omitted. Parentheses for Unit remain two delimiters. The valid golden file is
`tests/fixtures/lexer/Symbol Table.txt`; compare it to newly generated bytes.

The hand-written scanner advances a character-driven trie for identifier,
keyword, reserved and noise recognition. Terminal metadata is consulted only at
the identifier boundary; `letx` remains one identifier. Numeric states recognize
decimal/fraction/exponent and consume malformed numeric tails for recovery.
Quote states decode Text/Char escapes and validate scalar counts; comment states
recognize `//` through newline and non-nested `/* ... */` through first close.
Operators use maximal munch, including all seven arithmetic and nine Boolean/
relational forms. No generator, regex or whole-word keyword comparison is used.

Source snapshots own bytes/indexes; token spans borrow stable sources; results
own decoded literal/vector storage. Destroy results before sources. Library API
ownership is documented in include/ternfold/lexer.h. Reports publish atomically
through exclusive sibling files and reject source/report identity aliases.
The CLI never overwrites source files to produce a report.

Included C tests cover vocabulary, literals, boundaries, UTF-8/spans, recovery,
allocation failures, deterministic byte corpora, report bytes and CLI behavior.
Development compliance/review records live in the separate full C17 foundation.
