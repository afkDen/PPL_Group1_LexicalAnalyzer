Status is tracked in [progress](../progress.md) and [task graph](../tasks.json). Phase: **experimental**. Prerequisites: M14.

## Objective

Investigate a deeper semantic extension with an explicit go/no-go outcome.

## Implementation requirements

Compare library-level composition with first-class jointly accepted machine groups and optional transition assertions. Identify how nested rejects, emissions, dependencies and error precedence compose. Prototype bounded cases independently of production. Do not merge syntax or make static-proof claims until a normative extension and ADR state exactly what is checked.

## Tests and evidence

Counterexamples for partial inner acceptance, conflicting emissions and cyclic composition; prototype equivalence to explicit existing code on bounded cases.

Use `/ternfold-feature` for the impact assessment. Use `/ternfold-differential` for execution/ownership work. Record actual observed results; do not infer success from command availability.

## Acceptance criteria

- [ ] A written recommendation rejects or specifies one coherent extension.
- [ ] No experimental syntax silently enters 0.1.
- [ ] If proceeding, create a separately scoped implementation task with all affected layers.
- [ ] Affected specifications, examples and diagnostics are synchronized.
- [ ] Relevant tests and the canonical lint/type/test gate pass; no required gate is hidden by skips.
- [ ] Progress and task status include verification evidence and the next eligible task.
