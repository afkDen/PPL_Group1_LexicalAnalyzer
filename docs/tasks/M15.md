Status is tracked in [progress](../progress.md) and [task graph](../tasks.json). Phase: **advanced**. Prerequisites: M14.

## Objective

Make actual transition execution explainable without changing language behavior.

## Implementation requirements

First write an ADR and trace schema for executed writer/guard/emission events, source origins and old/candidate snapshots with bounded serialization. Add opt-in trace output to a separate file/stderr stream and replay inspection. Clearly distinguish static plan from execution; no always-on provenance. Preserve program stdout and fault order.

## Tests and evidence

Tracing-on/off observational equivalence, rejected/accepted/faulting steps, nested machines, trace truncation, replay determinism and no hidden side effects.

Use `/ternfold-feature` for the impact assessment. Use `/ternfold-differential` for execution/ownership work. Record actual observed results; do not infer success from command availability.
