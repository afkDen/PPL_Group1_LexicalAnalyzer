# M17 — Formatter and editor diagnostics

Status is tracked in [progress](../progress.md) and [task graph](../tasks.json). Phase: **advanced**. Prerequisites: M14.

## Objective

Make the language comfortable to edit without adding semantic features.

## Read first

AGENTS.md; docs/codex-handoff.md; docs/grammar.md; docs/architecture.md; docs/compiler-pipeline.md.

## Files and ownership

src/ternfold/formatting/; src/ternfold/editor/; tests/test_formatter.py; tests/test_editor.py

These are intended modules, not a requirement to create placeholders. Keep phase dependencies from architecture.md. If the work exceeds one session, finish a coherent internal slice and record the remaining acceptance criteria without marking the task done.

## Implementation requirements

Write tooling ADR: trivia retention strategy, canonical formatting and incremental document snapshots. Begin with formatter token/trivia attachment, then a minimal LSP adapter for diagnostics/hover using existing checker. Convert byte/scalar positions to UTF-16 only at adapter. No second parser/typechecker or hosted service. Add protocol dependencies only if justified against a stdlib adapter.

## Tests and evidence

Format idempotence, parse/format AST equivalence, comments preserved, Unicode editor positions, stale-document diagnostics discarded, cancellation and malformed messages.

Use `/ternfold-feature` for the impact assessment. Use `/ternfold-differential` for execution/ownership work. Record actual observed results; do not infer success from command availability.

## Acceptance criteria

- [ ] Formatting never changes behavior or loses comments.
- [ ] Editor feedback reuses the source-of-truth compiler.
- [ ] All tools remain usable offline.
- [ ] Affected specifications, examples and diagnostics are synchronized.
- [ ] Relevant tests and the canonical lint/type/test gate pass; no required gate is hidden by skips.
- [ ] Progress and task status include verification evidence and the next eligible task.

## Verification commands

```sh
.venv/bin/python scripts/dev.py check
.venv/bin/python scripts/audit_docs.py
```

Add `.venv/bin/python -m pytest tests/test_<owning_phase>.py` using the actual test filename created in this task. At M10 onward, `.venv/bin/python scripts/test_native.py` becomes a required additional gate for native changes (the script is created by M10, not available in M00). Packaging changes also run `.venv/bin/python scripts/dev.py build` and an installed-wheel smoke test. The task must document new exact executable commands it introduces before completion.
