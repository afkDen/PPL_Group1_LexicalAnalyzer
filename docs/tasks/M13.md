# M13 — Transactional REPL and usability polish

Status is tracked in [progress](../progress.md) and [task graph](../tasks.json). Phase: **complete**. Prerequisites: M12.

## Objective

Provide a practical session tool without alternate language semantics.

## Read first

AGENTS.md; docs/codex-handoff.md; docs/compiler-pipeline.md (REPL); docs/language-spec.md; docs/runtime.md.

## Files and ownership

src/ternfold/repl.py; src/ternfold/cli.py; tests/test_repl.py; docs/compiler-pipeline.md

These are intended modules, not a requirement to create placeholders. Keep phase dependencies from architecture.md. If the work exceeds one session, finish a coherent internal slice and record the remaining acceptance criteria without marking the task done.

## Implementation requirements

Token-aware multiline input, session module/bindings, same compiler pipeline, reset/load/type/plan/quit commands, bounded debug value display. A failed unit/load leaves session state unchanged. Reject values are successful evaluations. Preserve source locations for virtual REPL files and keep retained closures/snapshots valid.

## Tests and evidence

Scripted sessions for declarations/closures, unknown commands, incomplete strings/braces, failed loads, type errors, runtime faults, Reject handling, reset and EOF. TTY-independent transcript tests.

Use `/ternfold-feature` for the impact assessment. Use `/ternfold-differential` for execution/ownership work. Record actual observed results; do not infer success from command availability.

## Acceptance criteria

- [ ] REPL never uses Python evaluation of language source.
- [ ] State commits only after successful unit compilation and evaluation.
- [ ] Documented commands and meaningful errors work in captured sessions.
- [ ] Affected specifications, examples and diagnostics are synchronized.
- [ ] Relevant tests and the canonical lint/type/test gate pass; no required gate is hidden by skips.
- [ ] Progress and task status include verification evidence and the next eligible task.
