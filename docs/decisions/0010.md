# ADR 0010 — Real division and finite statically typed Float

Status: **accepted**, 2026-10-27.
Authority: direct human requirement update during M07; professor clarified
`/7` and `/9` as mandatory operator counts, with `/` real division and `div`
integer division. Numerical implementation is assigned to C01 and remains unverified until its gates pass.

## Problem and compatibility

ADR 0009 retained truncating Int `/` and floor Int `div`. That distinction fails
the clarified rubric: `7 / 2` must have a mathematically meaningful fractional
result. Seven arithmetic operators are `+ - / * % div ^`; nine Boolean/relational
operators are `&& || ! > < == != >= <=`. Every operator needs independent
recognition, typing, boundary and applicable execution tests. Short-circuiting
and immutable machine semantics remain unchanged.

Historical M03–M06 acceptance records remain truthful for the earlier contract;
they do not verify the correction. Existing `int_text(a / b)` source must change
to a real formatter or explicit conversion, or use `div` when integer division
was intended. Do not silently change it to a different quotient. Existing `div`
and `%` negative-operand behavior should remain compatible unless review finds
a compelling requirement conflict. M07 graph work continues; corrective C01
must verify lexical/type/constant contracts before M08 Core proceeds.

## Alternatives

1. Keep both operators Int-valued or merely rename them: rejected because real
   division is mandatory.
2. Make `/` produce exact rational values: mathematically strong but requires
   arbitrary-precision numerator/denominator ownership, normalization and a new
   native runtime dependency/implementation. This exceeds the smallest course
   correction and complicates overflow/equality/layout contracts.
3. Fixed decimal or scaled Int: bounded decimal division needs an arbitrary
   precision/scale policy and still cannot represent all real quotients.
4. Add a monomorphic finite IEEE 754 binary64 `Float`: familiar static type,
   clear native representation, bounded runtime footprint, explicit rounding
   and fault rules. Selected after independent High semantic and general review.

## Selected semantics

- `Float` is a primitive data-only/equality-capable type containing finite
  binary64 values. Operations round to nearest, ties to even. Subnormal values
  are supported; underflow to zero is accepted. Canonicalize either signed zero
  to positive zero. NaN and infinities are never language values.
- Decimal Float literals contain a fractional part or a decimal exponent:
  `(0|[1-9][0-9]*)(\.[0-9]+([eE][+-]?[0-9]+)?|[eE][+-]?[0-9]+)`.
  Signs remain separate tokens. Leading zeros remain invalid. `.5` and `1.` are
  not Float literals. Keep original lexeme/spans through AST; convert once by
  correctly rounded decimal-to-binary64 conversion. Finite underflow is legal;
  a nonfinite literal is E301. Malformed numeric runs use E102 with explicit
  recovery boundaries; they cannot masquerade as valid Float tokens. A dot
  joins a number only if followed by a digit. An adjacent e/E attempts an
  exponent, consuming at most one optional sign and requiring digits. Missing
  exponent digits, identifier suffixes, repeated exponents, and a second dot
  followed by a digit are E102. Extend invalid runs through ASCII alphanumeric/
  underscore and dots only when followed by a digit; +/- joins only an
  exponent-sign position. Preserve punctuation, whitespace and comments.
  `1.foo` is Int/Dot/Ident; `1.2.foo` is Float/Dot/Ident; `1e++2` is INVALID
  `1e+`, Plus, Int; `1efoo.bar` is INVALID `1efoo`, Dot, Ident.
  Malformed syntax wins over range checking: `1e999foo` is E102, while a
  well-formed nonfinite `1e999` is E301.
- `/` accepts any Int/Float operand pair and always returns Float: convert
  each Int operand independently to binary64 by nearest-even, retain Float
  operands, then perform rounded real division. Thus `5/2/2` is Float 1.25. A zero denominator
  faults R002. This explicitly permits approximation for Int magnitudes beyond
  2^53; it is not exact rational division.
- `+ - *` preserve matching Int or Float types. Comparisons/equality require
  matching numeric types. Other Int/Float mixing is E302; use explicit
  `int_float(Int) -> Float`. Unary minus preserves the type.
- `div` and `%` remain Int-only. `div` rounds toward negative infinity; `%`
  retains the dividend-sign remainder from truncating quotient. Thus `%` is not
  defined by the floor `div` quotient. Both reject zero with R002 and Int
  minimum divided/remaindered by -1 with R001, preserving the checked domain.
- `Int ^ Int -> Int` retains nonnegative exponent and checked exponentiation by
  squaring; negative exponent is R005. `Float ^ Int -> Float` uses the same
  explicit squaring order, with reciprocal-first base for negative exponents.
  Zero to a negative exponent is R002; either type to exponent zero is one.
  Float exponents are E302. Each intermediate operation rounds/checks; avoid
  needless final squaring. This avoids platform `pow` differences.
- Power's exact sequence is result=one, factor=base (or rounded reciprocal
  for a negative exponent), magnitude=absolute exponent in an unsigned/wider
  representation. While magnitude is nonzero: if odd, multiply/check result by
  factor; halve magnitude; if still nonzero, square/check factor. This order
  includes intermediate faults and avoids a needless final square. Base and
  exponent expressions evaluate normally even when the exponent is zero.
- A nonfinite Float arithmetic/conversion result is R001 at the original
  operation span; finite underflow is legal. Closed initializer faults remain
  E306 at that operation span. No Float fault becomes typed rejection.
- `float_int(Float) -> Option[Int]` truncates toward zero first, then tests
  Int representability and returns None outside bounds; in particular
  `float_int(int_float(9223372036854775807))` is None; no UB-prone native cast before a range check.
- Float literal patterns have the same rounded numerical value domain and need
  a wildcard/binder residual. Equal rounded literals are duplicate coverage;
  normalized zeros compare equal. No NaN exceptions complicate equality.
- `float_text(Float) -> Text` uses exactly 17 significant decimal digits,
  correctly rounded nearest/ties-even from the exact binary value, then trims
  fractional trailing zeros while retaining one fractional digit. Scientific
  form uses one digit before the dot, lowercase `e`, no redundant positive sign
  or exponent zeros. Zero is `0.0e0`. Decimal rounding precedes trimming and may
  carry into a new exponent. The definition uses exact integer-ratio decimal
  rounding; Python repr and C printf do not define language formatting.

## Cross-phase implementation and evidence

C01 amends the existing M03 lexer/report/automata, M04 AST/parser, M05 primitive
reservations, M06 types/constants/patterns and M07 generic plan integration.
Keep earlier phase APIs and history. Do not execute AST programs. M08 extends
Core constants/type/verifier; M09 and M10/M11 implement the same checked numeric
contract in the interpreter and C17 runtime/backend. Serialize native Float
constant bits rather than reparsing locale-sensitive source text.

Native capability probes must establish binary64 representation, nearest-even,
gradual underflow and operation rounding; disable contraction/fast-math/excess
precision that would change specified results. Fault codes and original spans,
bitwise finite results where meaningful, output bytes and exit status must be
compared. Independently test decimal rounding against exact integer/Fraction
oracles, halfway cases, signed extrema, subnormals, underflow/overflow, conversion
boundaries, both quotient/remainder sign combinations, power domains and
short-circuit faults. Verify all eleven rubric items with real `.tfd` source,
actual deterministic UTF-8 `Symbol Table.txt`, maximal munch and recovery spans.
Report Windows/POSIX evidence separately. Documentation alone never verifies
implementation.

## Independent review and selection

High semantic auditor Chandrasekhar and general reviewer Meitner independently
accepted the revised design: finite binary64, operator-specific `/` conversion,
precise formatting before trimming, bounded numeric recovery, preserved integer
division/remainder domains, conversions and explicit power operation order.
The supervisor selects alternative 4 under direct human authorization. No
routine user confirmation or second approval-gated plan is required.

Constant initializer syntax remains closed: explicit conversion/formatting
builtin calls are still forbidden there. `/` itself is a permitted primitive
constant expression. Adding Float must update prelude identities coherently;
never depend on stale hardcoded Option/Decision declaration indices.

This ADR supersedes ADR 0009 only for numerical `/`, additional Float behavior
and the clarified operator counts. The rest of ADR 0009 and all immutable-machine
contracts remain in force. Native support remains capability-gated and requires
actual parity evidence at M10/M11; selecting semantics does not verify it.
