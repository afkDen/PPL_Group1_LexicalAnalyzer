# ADR 0003: Static nominal types and limited inference

Status: accepted for target 0.1. Date: 2026-09-13.

## Context

The language must diagnose malformed transitions and matches before execution without a research-scale checker.

## Considered options

Dynamic, gradual, full HM generics, monomorphic nominal checking with fixed polymorphic builtins.

## Decision

Static nominal user types, required function signatures, local bidirectional inference, finite prelude schemes; no user generics/recursive data in 0.1.

## Rationale

Enough expressive data/functions to write real workflows with predictable checking and exhaustiveness.

## Consequences

Some code repeats monomorphic helpers. New generics, recursive types or effects require a type-model ADR.

This ADR explains the commitment; precise current semantics belong to the focused specification. Update or supersede this record when changing that commitment, and link the new record here.
